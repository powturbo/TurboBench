ГЛАВНЫЙ ИНСАЙТ: ACEAPEX = LZ77 (match-based). Любое преобразование, меняющее байтовый
порядок (packing/delta/transpose), РАЗРУШАЕТ повторы, которые LZ77 уже ловит → вредит.
Работает ТОЛЬКО группировка однородного (разделение потоков) — даёт LZ77 однородный вход
без ломки внутренних повторов. Согласуется со статьёй 1 ("stride-transform destroys LZ77 locality").
СЛЕДСТВИЕ: ACEAPEX preprocessing-стратегия ПРИНЦИПИАЛЬНО иная, чем у SPRING/GeneSqueeze
(энтропийные кодеки выигрывают от packing/transpose, т.к. нет сильного match-слоя; у ACEAPEX есть).
ДЛЯ СТАТЬИ: stream separation +10% — реальное улучшение, decoder неизменен. quality=68% массы,
но стандартные quality-трансформы конфликтуют с LZ77 → отдельное направление (lossy/специальный кодек).

ЧЕСТНЫЙ ВЫВОД (критично для статьи):
- zstd-19 ratio ВЫШЕ ACEAPEX на каждом потоке (1.2-1.55x). ACEAPEX НЕ выигрывает по ratio.
- Преимущество ACEAPEX = СКОРОСТЬ декода (165 GB/s GPU device-resident) + seek + параллелизм,
  при СОПОСТАВИМОМ (в пределах 1.2-1.5x) ratio. Это честная позиция, не "лучше всех по сжатию".
- Stream separation = универсальный +10-11% для FASTQ, подтверждён на ОБОИХ кодеках
  (zstd 273.7M→244.7M = +11%; ACEAPEX 339.9M→306.3M = +10%). Реальный защищаемый результат.
- kanzi DNA transform (AliasCodec packOnlyDNA, ANS0): 128M на seq — хуже ACEAPEX и zstd.
  Подтверждает: DNA-packing-трансформы не дают выигрыша на этих данных vs хороший LZ+entropy.
ИТОГ Закона Прорыва: stream separation работает (+10%); все байт-меняющие трансформы
(packing/delta/transpose/kanzi-DNA) — нет. ACEAPEX конкурирует скоростью, не ratio.
