# ACEAPEX — правила работы в репозитории

ACEAPEX — параллельный блочный LZ77-компрессор с произвольным доступом, формат ACEPX2
(`docs/FORMAT_ACEPX2.md`), ниша — геномы. Декодеры: C++ (`src/`), C99 (`c/`), Python
(`python/`), GPU (`aceapex_gpu.cu`). Решения — `docs/DECISIONS.md` (ADR), релизы —
`CHANGELOG.md`, схема тегов — ADR-013 (софт `vX.Y.Z`, `vN.0`/`paperN-v1` — статьи, заморожены).

## Протокол сессии
- Начало: прочитать `CLAUDE.md` -> `ROADMAP.md`.
- Перед задачей: прочитать ~/yasha-context/ACEAPEX/CONTEXT.md (короткое "сейчас") и последние 40 строк
  CONTEXT_<текущий месяц>.md.
- После задачи: строка-итог в CONTEXT_<текущий месяц>.md; если изменилось состояние (версия, PR, лучшие числа,
  открытое) — обновить CONTEXT.md; слом чужого механизма — запись BL-NNN в BREAKTHROUGH_LOG.md (правило BL).
  Карта файлов — README.md там же.
- Конец каждой задачи: обновить в `ROADMAP.md` разделы «Сейчас» / «Дальше» и статусы,
  закоммитить явными путями (оба репо).

## Судья
- `make test` = `./verify.sh HEAD`. Ожидание на ace-core: HEAD 50 pass / 0 fail (новые
  претензии поднимают pass; fail всегда 0).
- Результат пишется в `results/HEAD.json` — его не коммитить.

## Данные
- Корпуса `~/golden` и `~/CORPORA` — только чтение. Ничего не писать, не переименовывать.

## Коммиты
- Только с явными путями: `git add <путь>` / `git commit <пути>`. Никогда `git commit -a`
  и `git add -A` / `git add .`.
- Не коммитить `results/HEAD.json`, `sweep.log`, прочий локальный мусор.
- Коммит и push в рабочую ветку — сам (см. «Режим работы»).

## Ветки
- Новая работа — в отдельной ветке. В `main` — только после судьи 48/0 на ветке.
- Ветка `release` = последний выпущенный тег (на неё смотрят внешние подмодули, TurboBench). Двигается
  только при выпуске нового тега: fast-forward на тег (`git push origin <тег>^{}:release`). Иначе не трогать.

## Режим работы
- Молча: не описывать шаги, не пересказывать вывод команд, без промежуточных отчётов.
  Писать только: (а) вопрос, когда нужно решение пользователя; (б) итог задачи в 3-5 строках
  с числами; (в) ячейку/команду, которую выполняет пользователь (Colab).
- Идти по `ROADMAP.md` без подтверждений на каждом шаге: код, сборка, судья, коммиты и push
  в рабочую ветку — сам. Слияние в `main` — сам, только после `make test` с 0 fail, одной
  строкой в итоге.
- Остановиться и спросить только: решения из ROADMAP «Ждут решения пользователя»; всё, что
  выходит наружу (релизы, теги, PR, посты); изменение байтов архивов по умолчанию или ratio;
  удаление файлов; действия вне `~/pubrepo` и `~/yasha-context`.
- В конце каждой задачи — ROADMAP «Сейчас/Дальше» и строка CONTEXT_<текущий месяц>.md (протокол сессии).

## Общение
- Язык русский. Кратко, по делу, одна задача за раз.
- Факты и числа, без мета-комментариев.
- При реальном сомнении — спросить, а не угадывать.
