# D1: axf inside lzbench, the published single-thread method (2026-10-26)

ace-core (AMD EPYC 4344P), lzbench 2cc81a8 + local axf codec (`d1-lzbench-src/`: codec file, patch, run script),
plain `make` (no -march). `taskset -c 2 lzbench -eaxf,1,2,3,5,4/zxc,1/misa77,1 -t8,8 -o1c4 silesia.tar`,
7 runs per binary, median of the 7 decompression lines (raw log: `d1-lzbench-2026-10-26.log`).
`plain` = axf TU as lzbench builds it (no -mavx2, 32-byte copies fall back to 2 x 16); `avx2` = the same TU at -mavx2.
zxc and misa77 do their own runtime dispatch, so their two columns are the same code.

| codec | ratio | decomp. MB/s plain (min-max) | decomp. MB/s avx2 (min-max) | comp. MB/s |
|---|---|---|---|---|
| axf -1 (mm 16) | 61.34 % | 11471 (11403-11845) | 11708 (11580-12090) | 27 |
| axf -2 (mm 12) | 54.13 % | 11175 (11143-11658) | 11533 (11374-11865) | 25 |
| zxc 0.15.0 -1 | 61.67 % | 10648 (10603-10968) | 10664 (10611-10956) | 1023 |
| misa77 0.6.0 -1 | 42.64 % | 9613 (9587-10251) | 9772 (9605-10353) | 122 |
| axf -3 (mm 8) | 44.95 % | 9119 (9097-9682) | 9503 (9390-9986) | 25 |
| axf -4 (mm 5, optimal) | 39.20 % | 8424 (8420-9021) | 8853 (8742-9390) | 1.1 |
| axf -5 (mm 5) | 40.68 % | 7376 (7363-7901) | 7760 (7654-8216) | 26 |

- Same binary: axf -1 decompresses 7.7 % faster than zxc -1 (11471 vs 10648, plain) at a lower ratio (61.34 vs 61.67 %);
  axf -2 is 5.0 % faster at 54.13 %.
- Control: zxc -1 published 8151 MB/s on the 9555P; here 10648 -> factor 0.765 (not 0.82 as estimated from misa77).
  The 9555P figure for axf is not measured; at 0.765 the plain axf -1 would be ~8780 MB/s. Not a claim.
- -mavx2 on the axf TU: +2.1 % (-1) to +5.2 % (-5): a runtime-dispatch object would keep it; plain already passes.
- Compression of axf is 25-27 MB/s (single thread, greedy/lazy with a 1 MiB window); level 4 is 1.1 MB/s.
- lzbench verified every decode (its own compare); ratios equal the fair-harness runs (dm-minmatch, f1dm-gate).

## Part 2 (2026-10-27): safe decoder, compression by level

`d1b-lzbench-2026-10-27.log`: same binary (plain), -t8,8 -o1c4, 7 runs, median. zxc reported by lzbench as 0.15.0
in both parts (the version of lzbench #343). Safe decoder: `dec_block_safe` in `axf.h` (exact-size src and dst);
fuzz: `fuzz_safe.cpp`, `fuzz-safe-2026-10-27.log` (2 x 900 s under ASan + UBSan, 27.3 M mutants, no report; a
negative control with the margin cut to 64 bytes is caught by ASan).

| codec | ratio | decomp. MB/s | safe MB/s | safe cost | comp. MB/s |
|---|---|---|---|---|---|
| axf -1 | 61.34 % | 11523 | 10535 | -8.6 % | 26.5 |
| axf -2 | 54.13 % | 11237 | 10076 | -10.3 % | 25.1 |
| zxc 0.15.0 -1 | 61.67 % | 10634 | - | - | 1018 |
| misa77 0.6.0 -1 | 42.64 % | 9594 | 9464 | -1.4 % | 122 |
| axf -3 | 44.95 % | 9156 | 8317 | -9.2 % | 24.7 |
| axf -4 | 39.20 % | 8427 | 7559 | -10.3 % | 1.09 |
| axf -5 | 40.68 % | 7400 | 6659 | -10.0 % | 25.7 |

- axf safe -1 (10535) is 0.9 % **slower** than zxc -1 (10634): the lead holds for the unsafe decoder only
  (+8.4 % in this run). The safe cost of axf (8.6-10.3 %) is far above misa77's (1.4 %): open.
  A restructured safe loop (one combined branch, outlined slow path) measured slower (axf safe -1 ~10130) and was
  reverted.
- Compression by level (one run, -t8,8): 1: 27.7, 2: 26.1, 3: 25.7, 5: 26.7 MB/s; the optimal-parse levels
  4 / 6 / 7 / 8: 1.13 MB/s each (ratio 39.20 / 55.35 / 48.85 / 41.78 %, decomp. 8488 / 11598 / 10815 / 9345 MB/s).
  For TurboBench's rank (which weighs compression speed too) axf is 37-40x slower to compress than zxc -1.
- ARM: axf not run (no hardware). Open.
