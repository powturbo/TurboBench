# ACEAPEX 2.3.0 — 2026-10-26

A GPU library other programs link, a CPU decoder that moves 4x less memory, and a run script for any GPU machine.
Format ACEPX2 unchanged; archive bytes unchanged for a given libzstd. H100 figures from the RunPod run of 2026-10-02 (commit 834d5d1).

## What changed

- **GPU library, C ABI** (`src/aceapex_gpu.h`, shared library `libaceapex_gpu.so.1`, `docs/GPU_API.md`). Plan on the
  host once per archive, then asynchronous decodes on a stream: no allocation, no host copy, no synchronisation; range
  decode by coordinate; status bits instead of crashes. Frozen for 2.3, only additions later.
  - **API note:** `aceapex_gpu_plan_create(h_archive, in_bytes, uint64_t flags)` takes flags
    (`ACEAPEX_GPU_VALIDATE_ZSTD`; unknown bits -> `ACEAPEX_GPU_E_ARGS`); `aceapex_gpu_version()` returns
    `ACEAPEX_GPU_API_VERSION` (20300). Code written against development snapshots without the flags argument passes 0.
  - **Untrusted archives:** the open profile, or `ACEAPEX_GPU_VALIDATE_ZSTD`. nvCOMP 5.3.0.16 does not return on some
    corrupt zstd frames (standalone repro: `verify/repro/nvcomp_zstd_hang/`); the flag decodes every frame with
    libzstd on the host first (T2T: 191 495 frames in 78 ms on 16 threads).
- **GPU decode**: rANS refill from a register window, exception bytes folded into the 16-byte bases store, run ends
  in shared memory, 16-byte copies. AX_GPU_TILE (a block's literals built in shared memory, no literal stream) is in
  the code and off until measured.
- **CPU decode**: AVX2 rANS; literal tiles in L2 instead of a 3 GB intermediate literal stream; non-temporal output;
  compressed streams read in place; huge pages; default thread budget = physical cores; no 8 MiB of TLS per thread.
- **Streaming decode**: `aceapex_decompress_stream` (read and write callbacks) and `aceapex d -c`: a 3 GB genome
  through 35 MB of memory at 14 GB/s.
- **GPU outputs larger than the card**: block-range plans (`aceapex_gpu_plan_create_blocks`), batches two in flight
  (`scripts/gpu_stream.cu`, `gpu_run.sh` ONE).

## Honest caveats

- Archive bytes change for one kind of input only: DNA with more than 65 535 literal chunks (~4 GiB of literals, e.g.
  three human assemblies in one file). 2.2.x fell back to the pre-2.1 literal layout there (ratio 3.36); 2.3 keeps the
  chunked layout and the DNA transform (4.24) and streams it. The 2.2.2 decoders read these archives
  (`results/litcap-2026-10-02.log`).

- The GPU library needs nvCOMP for zstd-profile archives; the open profile needs only CUDA.
- AVX-512 rANS brings nothing on Zen 4 (512-bit ops on 256-bit units); kept behind `AX_RANS_SIMD=512`.
- On 16 threads (SMT) small archives decode slower than on the 8 physical cores; the default budget follows that.
