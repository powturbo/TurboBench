# ACEAPEX 2.2.2 — the library ignores the environment

Bug-fix release (lzbench #336). Archive bytes are identical to 2.2.1 (18 of 18 archives: silesia/xml, chr1 and enwik8 x
levels 1-3 x 1/8 threads; fixtures unchanged). Format ACEPX2 unchanged.
DOI: [10.5281/zenodo.23090998](https://doi.org/10.5281/zenodo.23090998)

## Fixed
- **Results depended on 16 environment variables** (reported by Przemysław Skibiński in lzbench #336). The library read
  `ACEAPEX_BS`, `ACEAPEX_DUMP`, `AX_ATT`, `AX_ENC`, `AX_HLOG`, `AX_LIT`, `AX_MINL`, `AX_NOFLAT`, `AX_PROFILE`, `AX_SKIP`,
  `AX_TOK`, `FSE_CHUNK`, `LIT_CHUNK`, `LIT_LANES`, `LIT_LANES_DEC` and `LIT_LEVEL` from the environment, so the same
  benchmark gave different archives on different shells, and `LIT_LANES_DEC` started decode threads although the caller
  asked for one (lzbench `-I1`). 2.2.2 reads them through one `ax_getenv()` (`src/ax_env.h`) that returns NULL unless the
  build defines `ACEAPEX_ENV_TUNING`. The library is built without it (lzbench, TurboBench, any program linking it); the
  CLI, the C99 reader CLI `axdec`, the Python reader and the repository's tools are built with it, so they keep the knobs.

silesia/xml, level 1, one thread, zstd 1.5.7 (lzbench's), five settings of the variables:

| setting | 2.2.1 bytes | 2.2.2 bytes |
|---|---|---|
| none | 724378 | 724378 |
| `ACEAPEX_BS=16384` | 853990 | 724378 |
| `AX_PROFILE=open` | 812809 | 724378 |
| `AX_ENC=chain AX_HLOG=12 AX_MINL=8 AX_SKIP=1 AX_ATT=4 AX_NOFLAT=0` | 734621 | 724378 |
| `FSE_CHUNK=4096 LIT_CHUNK=65536 LIT_LANES=8 LIT_LEVEL=19 AX_TOK=rans AX_LIT=open LIT_LANES_DEC=8` | 829935 | 724378 |

Threads started by the library at `threads=1` with those variables set (strace): 7 in 2.2.1, 0 in 2.2.2. A new judge
claim (`head_env_ignored`) builds the library without `ACEAPEX_ENV_TUNING`, sets the variables and requires the same bytes
and no thread. In lzbench the update is commit 8c1eb14 of #336 (vendored files byte-identical to this tag); its FASTEST
alias now uses aceapex level 3.
