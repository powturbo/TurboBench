# ACEAPEX 2.3.1 — 2026-10-27

CLI streams stdin/stdout (`--in -`, `--out -`); empty or failed pipe input is an error, never an empty archive.
Format ACEPX2 unchanged; archive bytes unchanged: the library, the encoders and the decoders are those of 2.3.0.

## What changed

- `aceapex c --in - --out -` and `aceapex d --in - --out -`: the whole of stdin is read into an in-memory file, then
  the usual path runs (so a piped archive has the same bytes as the archive of the same file). `--in /dev/stdin`
  from a pipe works the same way; a regular file redirected to stdin is read in place.
- Fix: `cat f | aceapex c --in /dev/stdin` used to write an empty archive with exit code 0 (a pipe has size 0).
  An empty pipe or a read error is now exit code 1 with a message and no archive; a failed write of the archive
  is exit code 1 (it was unchecked).
- Judge: claim `head_cli_stdin` (`scripts/stdin_test.sh`): pipe round-trip on 5 MB of chr19 at 1 and 4 threads,
  piped archive == file archive, every conformance fixture decoded from a pipe, empty pipe -> exit code != 0.

## Checked on this tag (ace-core, AMD EPYC 4344P)

- `make test`: HEAD 0 fail.
- Edge cases through a pipe (`c | d`, md5): poly-A 100 / 333 bp, one sequence, one-character and empty names, IUPAC,
  lowercase masks, mixed line lengths, no final newline, RNA (U), protein, CRLF, T2T twice (6.3 GB), two runs at
  once in one directory (no files left): 21/21 bit-perfect.
