# ACEAPEX 2.4.1 — 2026-10-28

Build fix for Windows (MinGW). Nothing else changes: format, archive bytes, encoders and decoders are those of 2.4.0
(`release/v2.4.0.md`).

- `aceapex_main.cpp` used `pread` in the CLI's streaming paths (`d --out -`, the `faidx` index build). MinGW has no
  `pread`, so the library did not compile on Windows since 2.3.0, also inside lzbench (lzbench #355, four MinGW jobs).
  Positional reads now go through `ax_pread`: POSIX `pread`; on Windows `ReadFile` with an OVERLAPPED offset; 64-bit
  offsets; `O_BINARY` on those opens.
- Checked: the lzbench wrapper compiles with MinGW-w64 x86_64 and i686, clang, aarch64, armhf; Linux pipe test 36/36,
  conformance 27/27, streaming decode of a default and a fast archive, `faidx`, bit-perfect.
