# ACEAPEX 2.4.2 — 2026-10-28

Build fixes for gcc 9/10 and 32-bit ARMv5, found by the lzbench CI (#355). Nothing else changes: format, archive bytes,
encoders and decoders are those of 2.4.0 (`release/v2.4.0.md`); 2.4.1 fixed the MinGW `pread` build (`release/v2.4.1.md`).

- gcc 9/10 (also MinGW-w64 on gcc 10): `_mm256_cvtsi256_si32` (gcc 11+) replaced by
  `_mm_cvtsi128_si32(_mm256_castsi256_si128(x))`, the same instruction.
- 32-bit ARMv5: a 64-bit atomic counter in the fast profile's range batch (no lock-free form there, unresolved
  `__atomic_load_8`) is `size_t` now.
- Portability gate `scripts/portability_test.sh` in CI and the HEAD judge: MinGW-w64 x86_64/i686, gcc 10,
  arm-linux-gnueabi (no `__atomic_*_8`).
- Checked: the lzbench wrapper compiles with MinGW-w64 x86_64 and i686, gcc 10, gcc 13, clang, arm-linux-gnueabi;
  conformance, api round-trip, fast_api, bit-perfect.
